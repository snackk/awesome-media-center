# CrowdSec Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Detect and block suspicious HTTP requests (scanning, brute-force, known CVE probes) against the Traefik-exposed services, with CrowdSec's own surfaces (LAPI, dashboard) reachable only via Tailscale, never from the Internet.

**Architecture:** Enable Traefik's JSON access log (stdout, matching every other container's logging convention). A new `crowdsec` container tails that log through the **Docker API datasource** (no shared log volume) and runs CrowdSec's `traefik` + `http-cve` + `base-http-scenarios` collections. Traefik enforces decisions via the official `crowdsec-bouncer-traefik-plugin`, configured as a middleware through Docker labels on the Traefik container itself (same `${VAR:?...}` pattern already used everywhere), applied to every public-facing router (Emby, Seerr, Immich, Navidrome, HomeControl). CrowdSec's LAPI (port 8080) is never published to the host — Traefik reaches it by container DNS name on the `web` network. An optional local dashboard (`cscli dashboard`, Metabase-based) is bound to `127.0.0.1` and published as one more Tailscale Service, exactly like Portainer/Radarr/etc.

This repo has no test suite — "tests" below are the same two things already used in `docs/MIGRATION-UGREEN-DXP2800.md`: `docker compose config` to catch YAML/variable errors locally, and an explicit on-NAS verification command whose expected output is stated. Steps marked **(on NAS)** cannot be run from this checkout and must be run by the user over SSH/Tailscale after `git pull`.

**Tech Stack:** Docker Compose, Traefik v3 (file + docker providers), `crowdsecurity/crowdsec` image, `crowdsec-bouncer-traefik-plugin` (Yaegi plugin), optional `cscli dashboard` (Metabase).

**Spec:** This plan's spec is the conversation itself — no separate spec file exists. Key decisions carried over from it:
- Keep CrowdSec's LAPI and dashboard inside the tailnet only (no public exposure), matching how Portainer/*arr/Picard/Traefik-dashboard are already handled.
- Match existing conventions exactly: `x-common`/`${VAR:?Set VAR in .env}` style, `security_opt: no-new-privileges:true`, `logging.options.max-size/max-file`, `127.0.0.1:port:port` publishing + `tailscale/services.sh` entry for admin UIs, README "What is exposed" table kept in sync.

## Global Constraints

- Every new/changed env var follows `${VAR:?Set VAR in .env}` (or `?...may be empty` where applicable) — no silent defaults, per `.env.example`'s own header comment.
- Every new service gets `restart: unless-stopped`, `security_opt: [no-new-privileges:true]`, and `logging.options: {max-size: "10m", max-file: "3"}`, matching every existing service.
- No new host-published port may be reachable from the LAN/Internet without the same `127.0.0.1:` binding + Tailscale Service pattern used for Portainer/Radarr/Sonarr/Prowlarr/Profilarr/Transmission/Debrid/Picard/Traefik-dashboard.
- CrowdSec's LAPI (8080) is reached by Traefik only via the `web` Docker network's internal DNS (`crowdsec:8080`) — it is never bound to a host port.
- README's "What is exposed" table (`README.md:13-23`) and the Tailscale Services table (`README.md:148-164`) must stay accurate after every task that changes exposure.

## Review Focus

- **Bootstrap ordering**: Traefik's bouncer middleware requires `CROWDSEC_BOUNCER_KEY`, but that key can only be generated by running `cscli bouncers add` inside the already-running `crowdsec` container — if Task 3 is deployed before Task 2's container has produced a key, `docker compose up` for Traefik fails on the `:?` guard (intended, loud failure) or, worse, starts with a stale/blank key and fails closed. The runbook in Task 3 sequences this explicitly.
- **Fail-closed on LAPI outage**: if the `crowdsec` container is down or unreachable, the bouncer plugin's default behavior can block all traffic to every public service (Emby, Seerr, Immich, Navidrome, HomeControl) at once. Task 3 pins `crowdsecMode: live` with a `depends_on` + healthcheck condition and documents this single-point-of-failure explicitly in the README, rather than leaving it implicit.
- **Secrets leaking into the new access log / dashboard**: enabling `accessLog` naively would log full request headers (`Authorization`, API keys in query strings for Immich/Seerr) into a log that CrowdSec parses and a dashboard renders. Task 1's config explicitly drops sensitive headers.
- **Docker-socket read access is a real privilege grant**: mounting `/var/run/docker.sock:ro` into `crowdsec` (needed for the `docker` log datasource) grants it the ability to read every container's logs and inspect the whole Docker API, not just Traefik's. Task 2 documents this trade-off in the README the same way Portainer's full socket access is already documented, and `acquis.yaml` scopes log *collection* to the `traefik` container only.
- **Offline hub updates**: `COLLECTIONS=...` on the image triggers a `cscli hub update` + install against the internet on every start; if the NAS's WAN is down, CrowdSec must still start and enforce using its last-cached ruleset rather than crash-looping. Task 2's healthcheck targets the local LAPI, not the hub, so this is verified explicitly.

### Task 1: Enable Traefik's JSON access log, without leaking secrets

**Files:**
- Modify: `traefik/data/traefik.yml`
- Modify: `README.md` (Traefik section, around `README.md:73-79`)

**Interfaces:**
- Produces: Traefik writes one JSON line per request to stdout (consumed by Task 2's `docker` log datasource, which filters on `container_name: traefik`).

- [ ] **Step 1: Add the `accessLog` block to `traefik/data/traefik.yml`**

Add, after the top-level `log:` block:

```yaml
accessLog:
  format: json
  fields:
    headers:
      defaultMode: drop
      names:
        User-Agent: keep
        Content-Type: keep
```

No `filePath` key — omitting it makes Traefik write to stdout, which Docker already rotates per container (`logging.options.max-size`/`max-file`, set when Task 2 touches `traefik/docker-compose.yml`'s `depends_on`, but already true today for every other container — add the same `logging.options` block to the `traefik` service in `traefik/docker-compose.yml` if it does not already have one; it currently does per `traefik/docker-compose.yml:28-31`, so no change needed there for this step). `defaultMode: drop` strips every header (including `Authorization` and any cookie) by default; `names:` whitelists only the two harmless ones needed to spot scanners (bad/empty `User-Agent`) and bots.

- [ ] **Step 2: Validate the compose/config files parse**

Run: `docker compose -f traefik/docker-compose.yml config --quiet`
Expected: exits 0, no output (this only validates YAML + env substitution, not the file-provider config — Traefik itself validates `traefik.yml` on boot in Step 3).

- [ ] **Step 3 (on NAS): Restart Traefik and confirm JSON logs with headers dropped**

Run: `cd traefik && docker compose up -d && docker logs traefik --tail 5`
Expected: JSON lines like `{"level":"info","msg":"...", "RequestHost":"...", ...}` with no `request_Authorization` or `request_Cookie` field present in any line.

- [ ] **Step 4: Update README**

In the Traefik section (`README.md:73-79`), add one sentence noting access logging is on (JSON, stdout, sensitive headers dropped) and that it feeds CrowdSec (Task 2).

### Task 2: Add the CrowdSec agent (log analysis, no public exposure)

**Files:**
- Create: `crowdsec/docker-compose.yml`
- Create: `crowdsec/acquis.yaml`
- Modify: `.env.example`
- Modify: `README.md` (new "CrowdSec" subsection + exposure table)

**Interfaces:**
- Consumes: Traefik's stdout JSON access log (Task 1), read via the Docker API, not a shared volume.
- Produces: a `crowdsec` container reachable at `http://crowdsec:8080` from any container on the `web` network — the exact address Task 3's bouncer middleware uses.

- [ ] **Step 1: Write `crowdsec/acquis.yaml`**

```yaml
source: docker
container_name:
  - traefik
labels:
  type: traefik
```

This is the datasource config, not a test — it tells the agent which container's logs to tail and which parser family (`traefik`) to apply.

- [ ] **Step 2: Write `crowdsec/docker-compose.yml`**

```yaml
services:
  crowdsec:
    image: crowdsecurity/crowdsec:latest
    container_name: crowdsec
    restart: unless-stopped
    networks:
      - web
    environment:
      COLLECTIONS: "crowdsecurity/traefik crowdsecurity/http-cve crowdsecurity/base-http-scenarios"
      TZ: ${TZ:?Set TZ in .env}
    volumes:
      - ${CONFIG_ROOT:?Set CONFIG_ROOT in .env}/crowdsec:/etc/crowdsec
      - ${CONFIG_ROOT:?Set CONFIG_ROOT in .env}/crowdsec-data:/var/lib/crowdsec/data
      - ./acquis.yaml:/etc/crowdsec/acquis.yaml:ro
      - /var/run/docker.sock:/var/run/docker.sock:ro
    security_opt:
      - no-new-privileges:true
    healthcheck:
      test: ["CMD", "cscli", "lapi", "status"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 30s
    logging:
      options:
        max-size: "10m"
        max-file: "3"

networks:
  web:
    external: true
```

No `ports:` key at all — this is the mechanism that keeps the LAPI unreachable outside the `web` Docker network, satisfying "manter o crowdsec dentro da rede tailscale" together with Task 4 (the only thing that will ever be reachable from the tailnet is the optional dashboard, not the LAPI itself).

- [ ] **Step 3: Add new variables to `.env.example`**

Under a new `# ── CrowdSec ──` section:

```sh
# ── CrowdSec ─────────────────────────────────────────────────────────────────
# Bouncer API key for Traefik, generated AFTER the crowdsec container is first
# up: `docker exec crowdsec cscli bouncers add traefik-bouncer -o raw`. Leave
# unset until you have run that command (Traefik will refuse to start with the
# bouncer middleware enabled until this is set — see Task 3).
CROWDSEC_BOUNCER_KEY=change-me
```

- [ ] **Step 4: Validate compose file parses**

Run: `docker compose -f crowdsec/docker-compose.yml config --quiet`
Expected: exits 0.

- [ ] **Step 5 (on NAS): Bring the stack up and confirm it reads Traefik's logs**

Run:
```sh

cd crowdsec && docker compose up -d
sleep 10
docker exec crowdsec cscli metrics
```
Expected: a table including an `Acquisition Metrics` section with a row for `traefik` showing a non-zero `Lines read` count (proves the Docker-API datasource is tailing Traefik's stdout).

- [ ] **Step 6: Update README**

Add a "CrowdSec" subsection (near "Tailscale", `README.md:143`) describing: what it does, that it reads Traefik's Docker logs directly (no shared volume), that the LAPI is never published (only reachable on the `web` network), and the Docker-socket read-access trade-off (same framing as the existing Portainer paragraph, `README.md:81-83`). ### Task 3: Enforce CrowdSec decisions in Traefik (the bouncer)

**Files:**
- Modify: `traefik/docker-compose.yml`
- Modify: `traefik/data/traefik.yml`
- Modify: `arr/docker-compose.yml` (seerr router only)
- Modify: `emby/docker-compose.yml`
- Modify: `immich/docker-compose.yml`
- Modify: `navidrome/docker-compose.yml`
- Modify: `homecontrol/docker-compose.yml`

**Interfaces:**
- Consumes: `crowdsec:8080` (Task 2) as the LAPI backend; `CROWDSEC_BOUNCER_KEY` from `.env` (Task 2, Step 3).
- Produces: a Traefik middleware named `crowdsec` on the `docker` provider — referenced as `crowdsec@docker` in every public router's `middlewares` label, same way `secure-headers@file` is referenced today.

- [ ] **Step 1: Declare the plugin in `traefik/data/traefik.yml`**

Add a top-level block (static config — plugins cannot be declared dynamically):

```yaml
experimental:
  plugins:
    bouncer:
      moduleName: github.com/maxlerebourg/crowdsec-bouncer-traefik-plugin
      version: v1.4.2
```

Pin the exact version shown (do not use a floating tag) — check `https://github.com/maxlerebourg/crowdsec-bouncer-traefik-plugin/releases` for the current latest at implementation time and use that instead if newer; record whichever version is actually used in the commit message.

- [ ] **Step 2: Add the middleware definition as labels on the `traefik` service in `traefik/docker-compose.yml`**

Add under the existing `traefik` service (after its current `security_opt` block, `traefik/docker-compose.yml:21-22`):

```yaml
    labels:
      - "traefik.enable=true"
      - "traefik.http.middlewares.crowdsec.plugin.bouncer.enabled=true"
      - "traefik.http.middlewares.crowdsec.plugin.bouncer.crowdsecMode=live"
      - "traefik.http.middlewares.crowdsec.plugin.bouncer.crowdsecLapiScheme=http"
      - "traefik.http.middlewares.crowdsec.plugin.bouncer.crowdsecLapiHost=crowdsec:8080"
      - "traefik.http.middlewares.crowdsec.plugin.bouncer.crowdsecLapiKey=${CROWDSEC_BOUNCER_KEY:?Set CROWDSEC_BOUNCER_KEY in .env (see crowdsec/docker-compose.yml)}"
    depends_on:
      crowdsec:
        condition: service_healthy
```

`depends_on` with `condition: service_healthy` means Traefik will not start until `crowdsec`'s healthcheck (Task 2, Step 2) passes — this is the ordering guard called out in Review Focus. Note Traefik and CrowdSec now live in separate compose projects; `depends_on` only works within the same `docker compose up` invocation, so this is enforced by the **runbook order** below, not by Compose alone — document that explicitly in Step 5.

- [ ] **Step 3: Apply the middleware to every public router**

In each of `arr/docker-compose.yml` (seerr only), `emby/docker-compose.yml`, `immich/docker-compose.yml`, `navidrome/docker-compose.yml`, `homecontrol/docker-compose.yml`, change the existing line:

```yaml
      - "traefik.http.routers.<name>.middlewares=secure-headers@file"
```

to:

```yaml
      - "traefik.http.routers.<name>.middlewares=crowdsec@docker,secure-headers@file"
```

(`crowdsec` listed first so a blocked request never reaches the point where response headers would be added.)

- [ ] **Step 4: Validate every touched compose file parses**

Run: `for f in traefik arr emby immich navidrome homecontrol; do docker compose -f $f/docker-compose.yml config --quiet || echo "FAIL: $f"; done`
Expected: no `FAIL` lines.

- [ ] **Step 5 (on NAS): Generate the bouncer key, then bring Traefik up in the correct order**

```sh
# 1. crowdsec must already be up and healthy (Task 2, Step 5)
docker exec crowdsec cscli bouncers add traefik-bouncer -o raw
# -> copy the printed key into .env as CROWDSEC_BOUNCER_KEY
cd traefik && docker compose up -d
docker logs traefik --tail 20
```
Expected: no `":?Set CROWDSEC_BOUNCER_KEY"` error, and no plugin-load error; Traefik dashboard (`traefik.<tailnet>`) still shows all routers healthy.

- [ ] **Step 6 (on NAS): Prove the bouncer actually blocks something**

```sh
docker exec crowdsec cscli decisions add --ip 198.51.100.1 --duration 1m --reason "manual-test"
curl -s -o /dev/null -w "%{http_code}\n" -H "X-Forwarded-For: 198.51.100.1" https://emby.<domain>/
```
Expected: `403` (CrowdSec's default ban response code), then after 1 minute the same curl returns Emby's normal response. This is the one real end-to-end proof that detection → enforcement works; everything before it only proves wiring.

- [ ] **Step 7: Commit**

```bash
git add traefik/docker-compose.yml traefik/data/traefik.yml arr/docker-compose.yml emby/docker-compose.yml immich/docker-compose.yml navidrome/docker-compose.yml homecontrol/docker-compose.yml
git commit -m "feat(traefik): enforce CrowdSec decisions via bouncer plugin on all public routers"
```
